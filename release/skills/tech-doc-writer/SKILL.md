# 企业级技术文档写作风格

## 核心理念

技术文档应该像一位经验丰富的架构师在讲解方案：既有高屋建瓴的全局视角，又有细致入微的实现细节。文档不是简单的功能列表堆砌，而是有血有肉的系统叙述。

## 写作原则

### 1. 总起先行，分点随后

每个章节、每个分点列表之前，必须有总起性的叙述文字。这些文字起到"过渡"和"定位"的作用，帮助读者理解接下来内容的上下文和意义。

**错误写法（直接罗列）：**
```
### 设计原则

**分层解耦原则**：...
**领域驱动原则**：...
```

**正确写法（总起先行）：**
```
### 设计原则

为实现上述设计目标，本框架在架构设计过程中遵循以下核心原则，这些原则指导着系统的模块划分、技术选型和部署策略。

**分层解耦原则**：...
```

### 2. 背景引入，内容扎实

善用"基于xxx的背景"、"考虑到xxx的特点"、"为了解决xxx问题"等句式建立上下文。内容描述要有深度，不仅说明"是什么"，更要说明"为什么是这样"和"解决了什么问题"。

### 3. 技术描述准确具体

技术选型、版本号、组件名称、端口号等关键信息必须准确。避免模糊表述如"使用了某主流框架"，应该明确"基于Spring Boot 2.7.18"。

### 4. 表格配合叙述

表格用于展示结构化信息（功能清单、技术对比等），但表格前后必须有叙述性文字，不能突兀地直接出现表格。

### 5. 段落形式为主

文档内容以段落形式保存，方便阅读和复制。避免过度使用列表，列表适合并列的简短发语，不适合需要展开说明的内容。

### 6. 去掉装饰，注重实质

- 不使用emoji
- 不使用无意义的连接词
- 直接切入正题

## 文档结构模板

### 章节结构

```
# 文档标题

## 一、XXX概述
[总起段落：介绍本章要讲述的内容、背景和目的]

### 1.1 XXX背景
[背景叙述，1-2段]

### 1.2 XXX原则
[先有总起段，再分点列出各项原则，每项原则前有引导句]

## 二、XXX详细设计
[总起段落]

### 2.1 模块A
[总起句：A模块承担XXX职责，在系统中起到XXX作用]
[详细内容，包括表格、代码等]
```

### 分点列表前的引导句模式

```
[总起段落]

**原则一**：引导句 + 具体描述

**原则二**：引导句 + 具体描述
```

引导句示例：
- "强调系统各组件之间的独立性，通过接口契约进行通信"
- "立足于成熟稳定的企业级技术生态，满足复杂业务场景"
- "考虑到制造企业的实际生产环境特点，采用分层部署策略"

## 常用句式模板

### 背景引入句式
- "基于对XXX系统高并发、分布式、模块化等特性的考量..."
- "考虑到制造企业的实际生产环境特点..."
- "为解决传统单体架构在XXX场景下的局限性..."
- "在企业级应用开发中，许多业务场景如XXX具有通用性..."

### 目的说明句式
- "为了实现XXX目标，本框架..."
- "旨在为XXX提供一套完整的解决方案..."
- "为保障系统的稳定性和可维护性，需要..."

### 过渡句式
- "以下为各层的主要职责说明："
- "该层包含以下核心组件："
- "基于上述设计原则，具体实现如下："

### 总结句式
- "这些组件共同构成完整的技术架构体系"
- "形成高内聚低耦合的领域边界"
- "实现业务与技术关注的有效分离"

## 典型错误对照

| 错误写法 | 正确写法 |
|---------|---------|
| 直接出表格，无铺垫 | 先有叙述，再出表格 |
| 分点列表无总起 | 每个列表前有总起引导 |
| 技术描述模糊 | 明确版本号、组件名 |
| 列表项过长 | 改为叙述段落 |
| 缺少上下文 | 每节开头有背景说明 |
