# 附件管理通用规则模板

> 本文件为模板，每个项目应在 `CONTRIBUTING.md` 中基于本模板定义具体规则。

## 目录结构要求

```
50-attachments/
├── INDEX.md              # 唯一允许存在于根目录的非附件文件
├── {category-A}/         # 分类 A
├── {category-B}/         # 分类 B
└── {category-C}/         # 分类 C
```

## 通用约束

1. **根目录禁止直接存放附件**
   - 根目录只允许 `INDEX.md`
   - 所有附件必须放入子目录

2. **每个子目录内部自包含**
   - Markdown 文件引用的图片必须位于同一子目录
   - 禁止跨子目录引用（如 `../其他目录/xxx.png`）

3. **INDEX.md 强制同步**
   - 新增文件：在 INDEX.md 中追加一行
   - 更新文件：更新状态栏
   - 删除文件：从 INDEX.md 移除对应行

## 分类示例（常见分类，项目可自定义）

| 分类名 | 存放内容 |
|--------|----------|
| 技术方案/ | 设计文档、架构图、PPT |
| 调研记录/ | 会议纪要、现场照片、录音 |
| 项目计划/ | 计划表、里程碑、WBS |
| 参考资料/ | 第三方白皮书、截图、外部资料 |
| 业务知识/ | 培训材料、入门文档、业务说明 |

## 禁止行为（通用）

- 不要把临时文件、`.venv`、缓存文件提交到 Git
- 不要把完整研究目录从 `40-studies/` 复制到 `20-implementation/`
- 不要新建 Obsidian `.canvas` 文件（用 Mermaid Markdown 替代）
- 不要在 `50-attachments/` 根目录直接存放 Office 文档或图片
- 不要使用旧目录名：`素材/`、`附件/`、`调研截图/` 等
