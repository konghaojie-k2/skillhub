# 报告内容质量标准

本文档定义测试报告内容的质量要求和检查标准。

---

## 深度分析要求

### 禁止的数据罗列

❌ **差示例（仅罗列）**：
> 测试用例1通过，测试用例2失败，测试用例3通过，测试用例4失败...

❌ **差示例（只有统计）**：
> 本次测试共执行100个用例，通过85个，失败15个，通过率85%。

### 合格的业务洞察

✅ **好示例（包含原因分析）**：
> 测试结果显示，涉及图表渲染的用例失败率明显高于文本类用例（67% vs 12%）。
> 这表明当前模型在视觉信息处理方面存在系统性缺陷，建议优先优化图像理解能力。

✅ **好示例（包含业务意义）**：
> 与基准版本相比，响应时间P99指标恶化了23%。
> 这意味着在高并发场景下用户体验将显著下降，需要立即排查性能瓶颈。

---

## 质量检查清单

每个章节的 `content` 字段必须满足：

- [ ] **长度 ≥ 200字符**（约3-4句话）
- [ ] **包含至少1个推理词汇**（因为、所以、表明、说明、导致、反映、意味着）
- [ ] **解释"为什么会这样"**（原因分析）或 **"这意味着什么"**（业务意义）

---

## 各章节核心问题

每个章节必须回答以下核心问题：

| 章节 | 核心问题 | 必须包含 |
|------|----------|----------|
| 📊 测试结论摘要 | 本次测试最重要的发现是什么？ | 2-3条核心发现 + 建议 |
| 测试概述 | 测了什么？为什么测？ | 测试目的、范围说明 |
| 测试环境与配置 | 在什么环境下测的？ | 软件环境、工具版本 |
| 测试结果详情 | 具体数据背后的规律是什么？ | 数据洞察，非罗列 |
| 对比分析 | 与基准相比有什么变化？为什么？ | 差异 + 原因分析 |
| 专项分析 | 深度洞察：数据特征、规律、异常 | 自主发现的规律 |
| 典型案例分析 | 具体例子说明了什么？ | 案例 + 启示 |
| 问题与改进建议 | 有什么发现？如何改进？ | 可操作的建议 |
| 附录 | 支撑材料在哪里？ | 数据文件路径 |

---

## 内容深度评估标准

| 等级 | 描述 | 处理方式 |
|------|------|----------|
| **优秀** | 有独特洞察，发现了数据背后的规律或异常 | 通过 |
| **合格** | 有基本分析，解释了原因或业务意义 | 通过 |
| **浅层** | 只有描述，没有分析 | **需重写** |
| **罗列** | 仅列举数据，无分析 | **必须重写** |

---

## 常见反模式

### 1. 统计数字堆砌
```
❌ 错误：
通过率：85%
失败率：15%
平均响应时间：120ms
P99响应时间：350ms

✅ 正确：
虽然整体通过率达到85%，但P99响应时间较基准版本恶化了40%，
这表明在高负载场景下性能出现明显退化，建议优先排查数据库查询瓶颈。
```

### 2. 泛泛而谈
```
❌ 错误：
测试结果总体良好，大部分用例通过，少部分失败。

✅ 正确：
测试发现模型在处理包含否定词的指令时失败率高达45%，
显著高于其他类型指令（平均12%），建议针对性优化否定语义理解能力。
```

### 3. 无建议的问题陈述
```
❌ 错误：
发现有15个测试用例失败。

✅ 正确：
15个失败用例中，80%集中在图表理解场景。建议：
1) 扩充图表类训练数据；2) 增加图表解析专项模块。
```
