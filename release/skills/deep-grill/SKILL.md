# Deep Grill：维度感知深钻

## Overview

Deep Grill 是一种结构化的深度讨论方法，用于把复杂问题讨论清楚。

它解决两个常见痛点：
1. **讨论浮于表面**：问题太大，聊不透。
2. **过度钻入细节**：一个小维度无限深挖，反而忽略了和它有耦合的其他维度。

核心思想：**先画维度地图，再决定钻多深，钻完回拉看全局。**

## When to Use

适合以下场景：
- 复杂架构决策或技术选型
- 产品功能范围边界不清晰
- 需要暴露隐藏假设和风险
- 用户要求"把这个问题聊透""多挑战一下这个方案"
- 用户觉得 grill-me 太散、跳得太快

不适合：
- 简单事实查询
- 已经明确、只需执行的小任务

## Trigger Phrases

用户可能这样说：
- "深钻一下这个问题"
- "维度感知地讨论"
- "把这个问题盘透"
- "这几个问题互相有关系，一起聊"
- "不要钻太细，拉一层"
- "这个方案再挑战一下"

## Protocol

### Step 1：拉维度地图

不急着追问，先把大问题拆成关键维度。

常用维度：
- **用户/业务**：谁用？解决什么？价值是什么？
- **技术/实现**：怎么做？依赖什么？约束是什么？
- **数据/现状**：现有数据支持吗？质量如何？
- **风险/回滚**：最坏情况是什么？能回退吗？
- **成本/维护**：开发成本、运维成本、人力成本。
- **时间/节奏**：什么时候要上？分几阶段？

输出形式：
```
大问题
├── 维度 A：...
├── 维度 B：...
└── 维度 C：...
```

### Step 2：判断维度关系

对每个维度，判断它是：
- **独立维度**：可以单独深钻，不影响其他维度。
- **耦合维度**：和另一个维度互相影响，必须合并讨论。

耦合信号：
- 讨论 A 时频繁提到 B
- A 的决策会改变 B 的前提
- A 和 B 共享同一个约束或资源

处理方式：
- 耦合维度合并为一个"维度组"统一钻。
- 独立维度按优先级逐个钻。

### Step 3：选择钻入深度

每个维度选择深度等级，不是每个维度都要钻到底：

| 深度 | 名称 | 目标 |
|------|------|------|
| L1 | 理解 | 确认定义、范围、基本事实 |
| L2 | 澄清 | 追问假设、例外、边界条件 |
| L3 | 方案 | 列出可选方案及 tradeoff |
| L4 | 决策 | 明确选择及理由 |

选择原则：
- 关键维度、风险高的维度 → L3 或 L4
- 辅助维度 → L1 或 L2
- 信息不足的维度 → 先 L1，标记后续补充

### Step 4：逐维度深钻

对选中的维度，按 Socratic 方式追问，直到：
- 假设被澄清
- 风险被识别
- 方案或结论可落地

每轮追问后给用户一个"关闭信号"：
> "这个维度我们现在算聊清楚了吗？还是再往下钻一层？"

### Step 5：跨维度回拉

每钻完一个维度或维度组，回拉到大图：
> "我们在维度 X 上的结论是…… 这对维度 Y 有什么影响？"

目的：
- 防止维度间结论冲突
- 发现新的耦合点
- 确认大图是否还成立

### Step 6：收敛与决策摘要

当关键维度都钻到合适深度后，整理：
- 最终结论
- 关键决策及理由
- 剩余风险
- 下一步行动

## User Control Phrases

用户可以用这些短语调整节奏：

| 用户说 | 含义 |
|--------|------|
| "往上拉一层" | 当前维度钻太细，回到更粗粒度 |
| "这几个维度合并" | 识别到耦合，把多个维度放到一起讨论 |
| "这个问题钻太深了" | 停止当前维度的深挖，切换到下一个 |
| "先回到大图" | 暂停当前维度，重新看全局 |
| "这个维度够了" | 当前维度关闭，进入下一个 |
| "再挑战一下" | 对当前结论继续 adversarial 追问 |

## Example Flow

**用户**："我们要不要把模型推理从本地迁到云端？"

**Claude**：
> 好，我们用 deep-grill 来盘这个问题。我先拉一个维度地图：
> ```
> 是否迁到云端
> ├── 业务维度：谁需要云端推理？延迟要求？
> ├── 技术维度：云端架构、模型部署方式
> ├── 数据维度：数据上云是否合规？传输成本？
> ├── 成本维度：云端费用 vs 本地硬件/维护
> ├── 风险维度：网络中断、数据安全、供应商锁定
> └── 时间维度：迁移周期、分阶段方式
> ```
> 其中"技术维度"和"成本维度"可能强耦合——比如选 Serverless 还是常驻实例，直接影响费用。"数据维度"和"风险维度"也耦合。我们先从业务维度 L1 开始？

**用户**："可以。"

**Claude**：
> 业务维度 L1：当前本地推理的用户有哪些？迁云后新增或变更了哪些使用方？延迟要求是多少毫秒以内？

...（根据回答推进到 L2/L3，然后回拉）

## Anti-Patterns

不要这样用 deep-grill：
- ❌ 不拉维度地图直接开钻
- ❌ 每个维度都钻到 L4
- ❌ 在一个独立小维度上无限深挖
- ❌ 钻完一个维度不跨维度回拉
- ❌ 忽略用户"往上拉""合并维度"的信号

## Tips

- 维度地图不是一次定死的，讨论中可以随时新增或合并维度。
- 如果用户已经画好了维度地图，可以直接进入 Step 2。
- 深钻时保持礼貌和建设性，目标是"把方案想得更清楚"，不是"赢过用户"。
- 遇到信息不足的维度，明确标记为"待补充"，不要强行给结论。
